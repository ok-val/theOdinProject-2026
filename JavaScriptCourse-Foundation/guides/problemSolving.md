The primary thing that software developers do is ~={green}problem-solve=~. 
Learning programming and tools is only secondary to problem-solve.

> "Problem solving is writing an original program that performs a particular set of tasks and meets all stated constraints." - Think Like a Programmer - V. Anton Spraul

**Each problem is a set of constraints.** Whether if that is a small coding exercise or Google's recommendation engine. ⊕ For example, high performance and scalability may not matter too much in a coding exercise but it is the vital in building apps for thousands of users. 

The best way to learn problem-solve is to ~={yellow}BUILD PROGRAMS FOR REAL USERS=~. The practice you get with real world users and problem-solving, the better you will be prepared to handle actual pipelines.

## The three steps

### Understanding the problem

If I don't understand the problem, I won't know if I've successfully solved it.
BUT HOW EXACTLY? *How do I know if I've really understood the problem?*
Here's my rendition of what the article suggests:
* Explain the problem to a 5-years old duck, in plain language, no fluff.

### Plan first, code later

*Plan plan plan.* What, how, when, where, why in terms of these elements:
* Input 
* Output
* Vars
* Tools 

Your algorithm is essentially a recipe to solve a particular problem. The pseudocode is like a cookbook: the purpose of the code here is like instructions to build a meal, the recipe is not the meal itself.

### Divide and conquer or Decomposition

*Break down the problem into smaller parts, subproblems, subareas, regions, steps, cases, what have you.* And start small. 

Here's how I would approach decomposing FizzBuzz using pseudocode.

> Program takes user input int, outputs per line while counting towards the int:
> * initiate a count, starting at 0, stopping at user input int;
> * if multiple of 3 and not 5, print 'Fizz';
> * if multiple of 5 and not 3, print 'Buzz';
> * if multiple of 3 and 5, print 'FizzBuzz';
> * else, print counting int;
> * count += 1;
> * program stops when count == user input int;


### Pseudocode

*Pseudocode are just plain language, waiting to be translated into the destination language that you would be using.* 
It should help build the outline of what your script is doing in terms of the plan you've laid out.
