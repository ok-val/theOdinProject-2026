What is form validation?

Form validation is a group of techniques for setting input constraints or rules. It helps a user input the right thing in the right place.

These techniques essentiall communicate to the user whether they have broken any rules.

In terms of backend efficiency, validation protects backend systems from incorrect data.

In terms of user experience, it makes the input process less frustrating and simple to follow.

Basic built-in HTML validations

Required validation

This is an essential one. Use with the asterisk to indicate mandatory.

Min and max length

The attributes minlength and maxlength will pop a modal that with a message informing the user of how their input is invalid.

Note: minlength is not the same as required. This constraint only applies once the user has entered some chars. In other words, minlength starts at 1.

Both validation attributes are most commonly used for textarea widget.

Min/max for number range validation

Simple. min=""; max=""

Going below min value would prompt a warning modal. Also limits the increment slider/buttons

Going above max value would also prompt a modal with limits on increments.

Regex for pattern validation

Implemented by the attributet 'pattern'. Regex expressions normally indiciate starting and ending using ^ and $, respectively. This syntax resembles how matching attribute selector works.

Don't try to remember regex patterns. Just use one that's widely available.

Title attribute

For an additional interface besides from pop-up modals, I could also use the title attribute. This allows a cursor modal to appear after hovering on the field for a couple seconds.

title attribute accept a string.

:valid, :invalid, :user-valid, and :user-invalid

These are pseudo-classes for validation.

The key different between :valid and :user-valid is the timing of evaluation. :valid will evaluate immediate on page load. :user-valid will only evaluate after the user has interacted with and left the field.

Conclusion

There are limitations to built-in validations. They won't be able to access information beyond its field. So matching password input and confirmation or validating username availability is not possible.

Additionally, client-side validation is not enough. To ensure integrity, server-side validation must also be in place.
