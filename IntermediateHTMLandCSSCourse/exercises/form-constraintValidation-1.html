Look at the code of this form.

First, it uses a new attribute: novalidate, which I haven't seen before.
What is does is simply disable the default modals, leaving default constraints validation and other native browser behaviors intact. This attribute is used for when I want to create custom appearances for error message modals. Good to know!

The other attribute I haven't seen is aria-live. This basically indicates that the span will be updated and accessed not only by JS but also screen-reader users.

In this example, I use the novalidate attribute for the form. This precludes my ability to use the method .setCutomValiation() as seen in the previous part because this method targets the native browser error modals which I disabled with novalidate.

Instead, because novalidate wouldn't disable the default 'under-the-hood' behaviors of the Constraints Validation API, I can still check different properties of the ValidityState object to manipulate the behaviors of our custom message modal.
